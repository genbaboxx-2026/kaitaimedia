# Claude Code 実装タスク指示書 v0.1

Claude Codeに順番に渡すタスクの分割案。**一度にまとめて依頼せず、1タスクずつ完了を確認しながら進めること。**

事前に `CLAUDE.md` をリポジトリのルートに置いておく。

---

## タスク0：事前準備（人が行う）

Claude Codeでは実行できない作業。

1. GitHubリポジトリを作成
2. Supabaseでプロジェクトを作成し、以下を控える
   - Project URL
   - anon key
   - service role key
3. Anthropic（またはOpenAI）のAPIキーを取得
4. Cloudflareアカウントを作成
5. Slack Incoming Webhookを作成（後回し可）
6. ドメインを取得

---

## タスク1：プロジェクト初期化

```
Next.js 15（App Router、TypeScript、Tailwind CSS）でプロジェクトを初期化してください。
CLAUDE.mdに記載のディレクトリ構成を作成し、ESLintとtypecheckのスクリプトを設定してください。
.env.local.example を作成し、必要な環境変数のキーを列挙してください。
```

**完了確認**：`npm run dev` が起動し、`npm run typecheck` が通ること。

---

## タスク2：DBスキーマ

```
要件定義書の第8章と管理画面仕様書をもとに、Supabaseのマイグレーションを作成してください。

必要なテーブル：
- articles（記事本体。ステータス、本文、SEO情報、CTA参照を含む）
- article_versions（初稿・修正稿の履歴）
- themes（テーマ在庫）
- generation_logs（生成履歴）
- quality_checks（品質チェック結果）
- article_embeddings（重複判定用ベクトル。pgvector）
- settings（生成設定のキーバリュー）
- prompts（プロンプトとバージョン履歴）
- masters（マスタ情報。種別で分類）
- ctas（CTA）
- categories（カテゴリー）
- audit_logs（操作ログ）

pgvector拡張を有効にし、RLSポリシーも設定してください。
初期データとして、カテゴリー14件と生成設定のデフォルト値を投入するseedも作成してください。
```

**完了確認**：Supabase上でマイグレーションが適用され、型定義が生成できること。

```
公開サイトのページを実装してください。この段階ではダミーデータで構いません。

- トップページ（新着記事、カテゴリー導線、BAKUSOQ紹介ブロック）
- 記事一覧（ページネーション）
- カテゴリー別一覧
- 記事詳細（本文、目次、関連記事、CTA表示）
- 運営会社ページ
- BAKUSOQ紹介ページ
- 問い合わせページ
- プライバシーポリシー、利用規約

デザインは解体業界の実務者向けとして、可読性を優先した落ち着いたものにしてください。
モバイルファーストで実装してください。
```

**完了確認**：全ページが表示され、スマートフォン幅で崩れないこと。

## タスク4：公開サイトのデータ接続とSEO

```

あわせて以下のSEO要件を実装してください：
- 全ページのtitle / meta description / OGP
- 記事詳細の構造化データ（Article、publisherはGENBABOXX）
- パンくずリスト（構造化データ含む）
- sitemap.xml と robots.txt の自動生成
- キーワード検索機能
```

**完了確認**：構造化データがGoogleのリッチリザルトテストで検証できること。

## タスク8：AI呼び出しラッパー


## タスク9：品質チェック3層

**生成パイプラインより先にこれを作ること。** チェックが先にあれば、生成の出力をすぐ検証できる。

```
/lib/quality に品質チェックを実装してください。

第1層（機械判定）：
- 数値表現の検出（要件定義書6.1の正規表現。除外リストをマスタから取得）
- 文字数、見出し階層、禁止表現、CTA有無、画像有無
- SEOタイトル・メタディスクリプションの文字数
- リンク死活チェック
- 記事型Cのみ出典URLの有無

第2層（類似度判定）：
- タイトルと本文の埋め込みベクトルを生成
- pgvectorで過去記事とのコサイン類似度を算出
- 閾値は設定値から取得

第3層（AI判定）：
- 文章の自然さ、論理の一貫性、具体性の3項目のみを5段階評価
- 事実の正誤判定は行わせない

結果はquality_checksテーブルに項目単位で保存してください。
```

**完了確認**：意図的に数値を含めたテキストを渡すと、確実に検出されること。

## タスク10：生成パイプライン

```
/lib/generation に記事生成パイプラインを実装してください。
要件定義書5.1の処理フローに従ってください。

1. 自動生成の有効/無効を確認
2. テーマ在庫から未使用テーマを1件選定（優先度順、同一カテゴリー連続を回避）
3. 構成生成 → 本文生成 → SEO生成
4. 品質チェック実行
5. 不合格ならAI修正 → 再チェック（最大2回）
6. 合格なら自動公開トグルの状態に従って公開または下書きで保存
7. 3回目不合格は下書き保存＋エラーログ
8. 生成履歴をgeneration_logsに保存（初稿・最終稿・使用プロンプト・トークン数を含む）

scripts/generate-article.ts から手動実行できるようにしてください。
```

**完了確認**：手動実行で記事が1本生成され、履歴が保存されること。

## 進め方の注意

- **タスク9（品質チェック）をタスク10（生成）より先に作る。** 逆にすると、生成結果の良し悪しを判断する手段がないまま進むことになる。
- 各タスクの完了時に `npm run typecheck` と `npm run lint` を通す。
- タスク10が完了したら、自動公開トグルはOFFのまま20〜30本生成し、どのチェック項目で落ちるかを見てから閾値とプロンプトを調整する。
- テーマ在庫が空だとタスク10の検証ができないため、タスク6の完了時点で最低20本はテーマを登録しておく。

# 管理画面 仕様書 v0.1

Supabase一本化を前提とした管理画面の要件。認証は Supabase Auth（メールアドレス＋パスワード）。全ページ認証必須。

---

## 画面一覧

| # | 画面 | パス | 目的 |
|---|---|---|---|
| 1 | ダッシュボード | `/admin` | 全体状況の把握 |
| 2 | 記事一覧 | `/admin/articles` | 生成された記事の確認・公開判断 |
| 3 | 記事編集 | `/admin/articles/[id]` | 本文・SEO・CTAの修正 |
| 4 | テーマ管理 | `/admin/themes` | 記事テーマの在庫管理 |
| 5 | 生成設定 | `/admin/settings` | 自動公開トグル、生成ルール |
| 6 | プロンプト管理 | `/admin/prompts` | 各生成ステップのプロンプト編集 |
| 7 | マスタ管理 | `/admin/masters` | 用語集、禁止表現、BAKUSOQ情報 |
| 8 | CTA管理 | `/admin/cta` | CTAの文言・リンク先 |
| 9 | 生成履歴 | `/admin/logs` | 生成ログ・品質チェック結果 |

---

## 1. ダッシュボード

上部にステータスカードを並べる。

- 今月の公開記事数 / 下書き数 / 失敗数
- 品質チェック合格率（直近30本）
- テーマ在庫数（20件未満は警告表示）
- 今月のAI推定利用料（設定上限に対する消化率をバー表示）
- **自動公開トグルの現在の状態**（ON/OFFが一目でわかること）

下部に直近10件の生成履歴を簡易表示。

## 2. 記事一覧

本システムで最も使う画面。**一覧上で公開判断が完結すること**を重視する。

### 表示項目

| 列 | 内容 |
|---|---|
| ステータス | 公開 / 下書き / 公開停止 / 生成失敗（色分けバッジ） |
| タイトル | クリックで編集画面へ |
| カテゴリー | |
| 記事型 | A / B / C |
| 品質スコア | 3層の判定結果を「3/3合格」形式で表示 |
| 修正回数 | 0〜2 |
| 文字数 | |
| 生成日時 | |
| 公開日時 | |

### 機能

- **フィルタ**：ステータス、カテゴリー、記事型、期間、品質チェックの不合格項目別
- **ソート**：生成日時、公開日時、文字数、品質スコア
- **検索**：タイトル・本文の全文検索
- **一括操作**：チェックボックス選択 → 一括公開 / 一括下書きに戻す
- **クイックプレビュー**：行を展開すると本文冒頭300字とチェック結果の詳細を表示（編集画面に遷移せず判断できる）

### 不合格項目の表示

品質チェックで落ちた記事は、どの項目で落ちたかを一覧上にタグ表示する。

例：`数値検出` `文字数不足` `類似度0.91`

これにより「どのルールが厳しすぎるか」が運用しながら見える。

## 3. 記事編集

左右2カラム。左が編集、右がプレビュー。

### 編集項目

- タイトル
- 本文（Markdownエディタ。ツールバーは見出し・太字・リスト・リンク・画像の最小構成）
- カテゴリー（セレクト）
- タグ（複数選択）
- スラッグ（URL）
- アイキャッチ画像（テンプレート再生成ボタン＋手動アップロード）
- SEOタイトル（文字数カウンタ付き、32文字超で警告）
- メタディスクリプション（120文字超で警告）
- CTA（どのCTAを使うか選択）
- 関連記事（手動指定）
- 公開日時
- ステータス

### 補助機能

- **保存時に品質チェックを再実行**し、結果を表示（人が編集して数値を入れてしまった場合に気づける）
- **初稿との差分表示**：AIの初稿と現在の内容を比較できる。どこを人が直したかが蓄積されると、プロンプト改善の材料になる
- 変更履歴（誰がいつ編集したか）

## 5. 生成設定

すべてDBの `settings` テーブルに保存。コードに定数を持たない。

### 自動生成の制御

- **完全自動公開トグル**（ON：合格記事を即公開 / OFF：すべて下書き）
- 自動生成の一時停止トグル（生成自体を止める）
- 実行時刻
- 1日の生成本数

### 記事生成ルール

- 文字数の下限・上限
- 対象読者（経営者 / 見積担当 / 現場管理者）
- 文体（です・ます / だ・である）
- 専門用語のレベル
- 見出し数の目安
- 記事型A/B/Cの配分比率
- BAKUSOQ紹介の分量
- FAQセクションの有無
- 自動修正の上限回数

### 品質基準

各チェック項目について「有効/無効」と「閾値」を設定できる。

- 文字数の下限
- タイトル類似度の閾値（初期値0.90）
- 本文類似度の閾値（初期値0.85）
- AI判定の合格ライン（初期値3点）
- SEOタイトル・メタディスクリプションの文字数上限

### コスト制御

- 月間AI利用料の上限（超過時は生成を自動停止）
- 使用するAIモデルの選択

## 6. プロンプト管理

生成ステップごとにプロンプトを編集する。

| ステップ | 用途 |
|---|---|
| 構成生成 | 見出し構成をJSONで出力させる |
| 本文生成 | 構成をもとに本文を書かせる |
| SEO生成 | SEOタイトル・メタディスクリプション |
| 自動修正 | 不合格項目を渡して修正させる |
| AI品質判定 | 定性評価の3項目 |

### 機能

- テキストエリアで編集
- 差し込み変数の一覧表示（`{{theme}}` `{{article_type}}` `{{masters}}` など）
- **バージョン履歴**：過去のプロンプトを保存し、いつでも戻せる
- **テスト実行**：保存せずに1本試し生成し、結果を確認できる（重要。本番に反映する前に検証できる）

## 7. マスタ管理

タブ切り替えで以下を管理。

- 用語集（用語 / 正しい表記 / 説明）
- よくある質問（質問 / 回答）
- BAKUSOQ機能一覧（機能名 / 説明）※存在しない機能を書かせないための参照元
- BAKUSOQの強み
- 禁止表現リスト（表現 / 理由）
- 推奨表現リスト
- 数値検出の除外リスト（誤検知を防ぐ許可パターン）
- 記事型テンプレート（A / B / C の構成雛形）

いずれもCSVインポート・エクスポートに対応させる。

## 9. 生成履歴

### 一覧

生成日時、テーマ、結果（公開/下書き/失敗）、修正回数、トークン数、推定コスト、実行時間。

### 詳細

1件の生成について、以下をすべて表示する。

- 使用したプロンプト（構成・本文・修正の各段階）
- 参照したマスタ情報
- AIの初稿
- 修正後の各バージョン
- 最終稿
- 品質チェック結果（3層それぞれ、項目単位の合否と詳細）
- エラー内容
- トークン使用量とコスト
- 公開URL

### エラーログ

失敗した生成のみを抽出したビュー。原因別に集計を表示し、頻出する失敗パターンが把握できるようにする。

---

## 共通仕様

- レスポンシブ対応（管理画面はPC優先、スマートフォンでも一覧確認は可能に）
- 一覧系はページネーション（50件/ページ）
- 削除操作は確認ダイアログ必須
- 認証はSupabase Auth。未認証は `/admin/login` へリダイレクト
- 操作ログ（誰がいつ何を変更したか）を `audit_logs` に記録
